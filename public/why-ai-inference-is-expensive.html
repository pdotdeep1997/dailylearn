Why Running AI Costs More Than Building It

Training a large model is a one-time megaproject. Inference — actually answering your prompts — is the bill that never stops, and it's bottlenecked somewhere surprising.

You’d think the expensive part of AI is training — the months of thousands of GPUs crunching the internet. That’s a huge one-time cost. But for a model serving millions of users, the spending that dominates over its lifetime is inference: the compute burned every single time it generates a response. And the reason each answer is costly isn’t what most people assume. It’s rarely about raw math horsepower — it’s about memory bandwidth.

Training once vs. answering forever

Training is a fixed investment: run it, get a set of weights, done. Inference is what happens on every request, forever, for every user. A model like a large LLM might be trained once but then run billions of times. Multiply a few cents of GPU time by billions of calls and inference quietly becomes the larger line item — which is why AI companies obsess over shaving milliseconds off each token.

How an LLM actually generates text

An LLM writes one token at a time (a token ≈ a short chunk of a word). To produce each new token, it runs a full forward pass through the entire network, then feeds the result back in to produce the next one — an inherently sequential loop. You can’t compute token #50 until you have token #49.

There are two phases. Prefill reads your whole prompt at once — highly parallel and efficient. Decode then generates the response token-by-token, and this is the slow, expensive part.

💡
The real bottleneck: memory bandwidth

To generate each token, the GPU must read the model’s billions of weights out of memory and into the compute cores — then do so again for the very next token. For single-stream decoding, the chips can multiply numbers far faster than they can fetch the weights to multiply. So the GPU spends much of its time waiting for memory, not computing. Inference is memory-bandwidth bound, which is why it can leave expensive compute cores idle.

What happens per token generated

  1. 1

    Load the relevant model weights from GPU memory into the compute cores.

  2. 2

    Run one forward pass over the current context to produce a probability distribution.

  3. 3

    Pick the next token and append it to the output.

  4. 4

    Update the KV cache — stored intermediate results so earlier tokens don’t have to be recomputed. This cache grows with every token and eats memory.

  5. 5

    Repeat for the next token. Longer outputs = more sequential steps = more cost.

How providers fight the cost

Because the weights get read anyway, providers batch many users’ requests together so each expensive memory read serves lots of people at once — the single biggest efficiency lever, though it trades off against latency. They also quantize models (store weights in 8- or 4-bit instead of 16-bit) to move less data, use smarter attention and KV-cache tricks, and route easy queries to smaller models. The economics are stark enough that a large slice of the AI industry’s capital is now aimed not at training bigger models, but at making inference cheaper — because that’s the cost that scales with success.

The gist

  • Training is a one-time cost; inference recurs on every request and dominates over a model’s life.

  • LLMs generate one token at a time in a sequential loop — that’s inherently hard to speed up.

  • The bottleneck is usually memory bandwidth, not compute: the GPU waits to fetch weights.

  • The KV cache avoids recomputation but grows with every token and consumes memory.

  • Providers cut costs via batching, quantization, and cache tricks — inference efficiency is where much of the industry’s money now goes.

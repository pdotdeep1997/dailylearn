What a Computer Really Does

Strip away the apps, the windows, the AI — underneath, a computer is doing one stupefyingly simple thing, billions of times a second.

A modern laptop can render a movie, run a game, and hold a video call at once. It feels impossibly clever. But underneath every bit of that is a machine doing something almost embarrassingly simple: fetch an instruction, do it, repeat. No magic, no understanding — just a mindless loop run so fast that intelligence appears. Today’s lesson is the bedrock of this whole track: once you see the loop, every layer above it — operating systems, databases, the cloud — becomes a story about hiding that simplicity behind useful lies.

The whole machine, in one loop

At the center of a computer is the CPU. It does nothing but repeat a cycle called fetch–decode–execute:

  1. Fetch the next instruction from memory.
  2. Decode what it means (add? compare? jump?).
  3. Execute it — usually a tiny operation on a couple of numbers.

Then it does it again. And again. A few billion times per second. Every program you’ve ever run is just a long list of these micro-instructions. The CPU has no idea it’s “running a browser” — it only ever sees the next instruction.

💡
The one idea to keep

Speed plus simplicity looks like intelligence. The CPU is dumb; it’s just fast and relentless. Everything that feels smart about computers is built on stacking simple, reliable operations — a theme we’ll hit again and again in this track.

Why we build 'abstraction layers'

No human writes billions of raw CPU instructions by hand. So we build layers, each hiding the messy layer below and offering something friendlier:

  • Machine code (raw instructions) →
  • Programming languages (Python, C) that compile down to it →
  • Operating systems that manage memory and hardware for you →
  • Applications you actually click on.

Each layer is a useful lie: it lets you ignore the details underneath so you can think bigger. When you write print("hi"), you’re standing on a tower of abstractions that eventually becomes fetch–decode–execute. Almost all of software engineering is choosing the right layer to think at — and knowing that a real, simple machine is always at the bottom.

The gist

  • A CPU endlessly repeats one loop: fetch → decode → execute.

  • Every program is just a long list of these tiny instructions; the CPU never sees the ‘big picture’.

  • Apparent intelligence comes from simple operations run incredibly fast, not from cleverness.

  • Software is built as abstraction layers, each hiding the one below (machine code → languages → OS → apps).

  • Good engineering is picking the right layer to think at — while remembering a simple machine sits at the bottom.
